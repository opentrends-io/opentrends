## Known limits

- 不承诺所有积压马上清空：仍受每分钟 12 次、全局并发 2、每任务 3 次及每日双上限控制。Preview 只持续翻译既有内容，其他抓取定时仍关闭。
- 超大输入本轮仍按保守预留计入尝试，未实际调用模型时可能高估站内费用；不会超支，后续可增加按字节拆批与零用量结算。未知供应商用量不按零计。
- 完整账户账单不可由已下线的供应商余额 API 获得；站内成本只是按用量和配置单价估算。
- 补漏扫描当前 246 个来源，每 tick 16 个，正常调度下完整轮转约 16 分钟；不能承诺遗漏登记的新条目一定在浏览器 5 分钟自动查询窗口内完成。正常后台 ingest 直接登记，不等这轮扫描。Preview 没有开启完整抓取定时器，独立来源 GET 引起的新快照可能先显示“等待后台登记”，这一状态已实测并与“排队中”区分。生产上线前应先预热完整一轮；热点来源优先补漏可作为下一批性能优化，不扩大本批。
