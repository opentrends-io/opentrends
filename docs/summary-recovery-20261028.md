# 摘要请求恢复与翻译延迟检查（2026-10-28）

## 当批边界

- 必须交付：刷新失败保留同一摘要的最近成功内容及引用；自动重试有上限；手动重试可恢复；切换板块/语言/时间范围取消旧请求，不混用摘要。
- 明确不做：更换模型、增加后台并发/费用、修改翻译缓存策略、生产发布、云端配置或凭据变更。
- 阻断项：旧摘要丢失、跨板块串内容、无界重试、原有摘要交互回归、秘密泄漏或未授权外部写入。
- 收口：定向测试 → 实际组件的隔离浏览器验收 → 全仓单测/检查 → 留存代码和检查结论。发布需下一步明确授权。

## 实现

- `summary-request.ts` 统一网络错误、流读取失败、202/408/429/5xx 的重试预算：首次请求 + 最多 3 次重试。
- 一般错误退避为 1/3/8 秒；遵守 `Retry-After`，超过 60 秒则停止自动重试，不擅自提前重试。202 缺少该响应头时按 30 秒处理。其他 4xx 不自动重试；204 是正常空结果。
- 单次请求最多 120 秒，兼容关注摘要的现场生成（服务端允许首块等待 60 秒）；离开当前摘要时取消请求和等待定时器。
- 最近成功的摘要保持可读，新摘要完整成功后才替换；失败的部分内容不会写入成功缓存。无旧摘要时展示失败与重试按钮。
- 摘要身份控制生命周期，而不是来源数组的对象引用。后台刷新来源对象不会重置重试预算。
- 八种语言补齐恢复提示；手机标题栏允许自然换行，避免时间按钮与错误提示重叠。

## 翻译为什么显得慢

### 线上抽样事实

只读检查正式接口 `/api/trends/featured?items=30&lang=zh&translations=background`：

- HTTP 200，约 1.37 秒，`X-Trends-Cache: stale`。
- Hacker News 30/30 条带有 `original`（已有翻译记录），27/30 标题含中文；The Verge 10/10 带翻译记录，10/10 标题含中文。
- `Cache-Control: public, max-age=60, s-maxage=300, stale-while-revalidate=600`。本次未收到 `Age` 或 `CF-Cache-Status`，不能据此断言发生了边缘缓存命中。
- 翻译记录不代表每个词都变为中文，产品名可以保留原文。这个抽样证明后台已有结果，不证明截图发生时或所有来源的任务都正常。

### 代码确认的延迟链

1. `translation-status.ts` 与 `TitleTranslationIndicator` 根据原文/本地化字段判断转圈，**不是后台任务的实时状态**，也不区分排队、失败或已完成但页面还旧。
2. `trends-query.ts` 在发现未翻译条目时每 10 秒重新请求；`load-trends.ts` 没有绕过浏览器 HTTP 缓存，因此重新请求不等于取得新版本。
3. 仍含待译条目的服务端整页缓存保留 60 秒，过期后先返回旧数据再后台刷新。翻译完成只清除当前实例内存中的页面缓存，不删除共享 KV 副本。
4. HTTP 响应还允许浏览器缓存 60 秒、共享缓存 300 秒及陈旧回源 600 秒。实际延迟取决于哪些层生效，不能把这些数字机械相加当作实测耗时。
5. 确实尚未翻译的内容需要后台工作：常规任务共用摘要队列；访问触发的补译有 20 秒预算、最多 60 个候选，每批 6 条、并发 4。大量缺失或供应商变慢时不会一次填满所有来源。

### 下一批建议（未实施）

优先打通翻译完成到读者页面的可见性：区分待译/完成页面缓存策略、以有界方式重新获取待译页面、让转圈能表达等待/失败而非永久“翻译中”。保持单条翻译缓存和成本上限。不要仅通过增加模型并发或反复重新生成来掩盖缓存滞后。

## known_limits

- 本次改善失败后的恢复，不宣称消除了底层偶发请求中断。
- 保留同一板块/语言/窗口/来源/关键词身份的当前会话缓存或 SSR 已有摘要；不把今日内容冒充本周内容，不新增跨浏览器的摘要持久化。
- 普通主题摘要读共享缓存；关注摘要可能现场生成。自动重试是有界的，但不能保证失败请求完全不产生模型费用；未修改服务端生成/计费逻辑。
- 尚未核验当前生产队列积压或模型耗时分布，不能将截图那次延迟归咎于特定模型。
